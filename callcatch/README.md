# «Перехват» — спасение потерянных обращений для автосервисов

Автосервисы не отвечают на 25–42% входящих звонков; 78% недозвонившихся уезжают
к первому ответившему конкуренту. «Перехват» ловит каждый непринятый звонок:
клиент в течение минуты получает SMS от имени сервиса, бот доводит его до записи
в свободный слот, администратор получает уведомление, владелец — еженедельный
отчёт с каждой спасённой записью поимённо.

Ключевое для бизнес-модели: **журнал записей ведётся на нашей стороне** —
атрибуция результата не зависит от CRM сервиса и не может быть «спрятана».

Зависимостей нет вообще — чистый Python 3.10+ (стандартная библиотека).

## Быстрый старт: демо для показа

```
python -m callcatch demo
```

Симулирует 3 недели жизни сервиса (~740 звонков, ~300 пропущенных) через
настоящий диалоговый движок и кладёт в `output/`:

- `демо_отчёт_владельцу.html` — воронка перехвата + каждая запись поимённо;
- `демо_тайный_аудит.html` — продажный отчёт «я звонил вам 6 раз, вы потеряли 4»;
- `демо_sms_переписка.txt` — как бот разговаривает с клиентами.

Живой дашборд по демо-данным:

```
python -m callcatch serve --db demo.db      # http://localhost:8040
```

## Как это работает в бою

```
Клиент звонит в сервис ──► занято / не берут / нерабочее время
        │
        ▼ (переадресация непринятых у оператора — одна настройка)
Виртуальный номер / АТС ──► POST /webhook/call
        │
        ▼
SMS клиенту от имени сервиса («не дозвонились — запишем без очереди»)
        │
Ответ клиента ──► POST /webhook/sms ──► бот: услуга? время? ──► запись в слот
        │                                        │
        ▼                                        ▼
Журнал записей (наш)                 уведомление администратору (Telegram)
        │
        ▼
Еженедельный HTML-отчёт владельцу: пропущено → перехвачено → записано → выручка
```

### Сервер и вебхуки

```
python -m callcatch serve [--port 8040] [--db имя.db]
```

- `POST /webhook/call?token=...` — событие звонка. Форматы: generic
  (`{"phone", "status": "missed"|"answered", "at"}`), Zadarma (`NOTIFY_END` +
  `disposition`), Novofon (`call_state`). См. [telephony.py](callcatch/telephony.py).
- `POST /webhook/sms?token=...` — входящее SMS: `{"phone", "text"}`.
- `GET /` — дашборд, `GET /report` — отчёт владельцу, `GET /health` — проверка.

Токен вебхуков: `CC_WEBHOOK_TOKEN` (по умолчанию dev-значение — смените в бою).

### Ручное тестирование без телефонии

```
python -m callcatch call +79161234567            # пропущенный звонок
python -m callcatch sms +79161234567 "нужна замена масла завтра утром"
python -m callcatch sms +79161234567 "да, давайте"
python -m callcatch report
```

### Тайный аудит (продажа)

```
python -m callcatch audit "СТО Гараж" no_answer --note "суббота 12:40"
python -m callcatch audit "СТО Гараж" answered
python -m callcatch audit-report "СТО Гараж" --calls-per-day 30
```

→ `output/аудит_СТО Гараж.html` — документ, который отправляется владельцу
холодным сообщением. Сценарий продажи — в [ПРОДАЖИ.md](ПРОДАЖИ.md).

## Настройка под сервис

[callcatch/config.py](callcatch/config.py): название/адрес, график работы,
вместимость (машин в час), услуги с ключевыми словами и ценами, тексты и
каденция — всё в одном файле. Боевые ключи — через переменные окружения:

| Переменная | Что это |
|---|---|
| `CC_SMS_PROVIDER` | `console` (по умолчанию, пишет в файл) или `smsru` |
| `CC_SMSRU_API_ID` | ключ API sms.ru |
| `CC_SMS_SENDER` | буквенный отправитель (согласуется с оператором) |
| `CC_TG_TOKEN`, `CC_TG_CHAT` | Telegram-бот для уведомлений администратору |
| `CC_WEBHOOK_TOKEN` | секрет вебхуков |
| `CC_PORT` | порт сервера |

## Голосовой ассистент (v2)

Тот же мозг, но в телефонной трубке: ассистентка «Алёна» отвечает на
переадресованный звонок живым синтезированным голосом, ведёт к записи,
двухступенчато отрабатывает «позовите человека» («мастер занят ремонтом, могу
записать сама» → «передам мастеру, перезвонит»), после записи шлёт
SMS-подтверждение, админу — расшифровку разговора.

Архитектура: распознавание/синтез делает телефонная платформа, мозг — наш
сервер. Рекомендуемая платформа — **МТС Exolve** (данные в РФ, 152-ФЗ);
контракт подключения и выбор платформы — [integrations/README.md](integrations/README.md),
эталонный адаптер — [voximplant_scenario.js](integrations/voximplant_scenario.js).
Эндпоинты мозга:

- `POST /api/voice/start` `{phone}` → приветствие или `reject` (бюджет/лимиты —
  тогда клиента догоняет SMS);
- `POST /api/voice/utterance` `{session_id, text, elapsed_sec}` → ответ + `continue|hangup`;
- `POST /api/voice/end` `{session_id, duration_sec}` → итог, себестоимость, расшифровка админу.

Предохранители (config.py): мягкое сворачивание с 180-й секунды, жёсткое
завершение на 300-й, максимум 12 реплик, 2 звонка с номера в день (записанные
клиенты — без лимита), дневной бюджет речевых сервисов с деградацией в SMS-режим.

Послушать, как разговаривает бот (текстом, без телефонии):

```
python -m callcatch voice-sim
```

## Диалоговый движок

Правила + конечный автомат: понимает услугу («что-то стучит» → диагностика),
время («завтра после 16», «в субботу утром», «к 15»), подтверждение/отказ/стоп.
Не понял дважды — передаёт администратору с уведомлением. Клиент перезвонил и
дозвонился сам — бот замолкает. Точка подключения GigaChat/YandexGPT —
`dialog.llm_reply()` (`USE_LLM` в конфиге).

## Право (кратко)

Бот отвечает на обращение самого клиента — это исполнение его запроса, а не
рекламная рассылка (ст. 18 38-ФЗ не задевается). Обработка номера — по поручению
сервиса (договор поручения, ч. 3 ст. 6 152-ФЗ). Слово «стоп»/«уберите номер»
останавливает переписку немедленно.
