# Auto-Service Automation

Два независимых инструмента для автосервисов, закрывающих две дырки, через которые утекает выручка. Первый ловит клиентов, до которых сервис не дозвонился, второй возвращает тех, кто перестал приезжать.

Оба написаны на Python 3.10+, работают автономно и запускаются одной командой в демо-режиме, поэтому посмотреть результат можно без реальных данных и без внешних сервисов.

## [Перехват](callcatch) · спасение потерянных обращений

Автосервисы не отвечают на четверть входящих звонков, и большинство недозвонившихся уезжает к первому ответившему конкуренту. Система ловит каждый непринятый звонок, отправляет клиенту SMS от имени сервиса, доводит диалог до записи в свободный слот, уведомляет администратора и присылает владельцу еженедельный отчёт с каждой спасённой записью.

Журнал записей ведётся на стороне системы, поэтому результат можно доказать независимо от CRM автосервиса.

Зависимостей нет, только стандартная библиотека. Есть HTTP-сервер с вебхуками под виртуальные номера и АТС, диалоговый движок, живой дашборд и заготовки интеграций.

```
python -m callcatch demo
python -m callcatch serve --db demo.db
```

## [Win-back](winback) · возврат уснувших клиентов

Сегментирует базу автосервиса по правилам, готовит персональные сообщения цепочками, считает атрибуцию возвращённой выручки и печатает отчёты для владельца. Колонки в выгрузке из CRM распознаются автоматически, порядок не важен.

Единственная зависимость, openpyxl.

```
pip install openpyxl
python -m winback demo
```

## Структура

```
callcatch/   перехват непринятых звонков, диалоговый движок, вебхуки, отчёты
winback/     сегментация базы, цепочки сообщений, атрибуция, отчёты
```

Подробная документация по каждому инструменту лежит в его папке.

## Про инженерные решения

Обе системы намеренно построены на детерминированной логике, без языковых моделей. Задачи здесь узкие и хорошо формализуются правилами, а цена ошибки высокая, потому что сообщение уходит живому клиенту от имени сервиса. Правила дают предсказуемость, нулевую стоимость запуска и возможность объяснить владельцу, почему система написала именно это.

Демо-режим генерирует синтетические данные и прогоняет через настоящий движок, а не через заглушки, поэтому отчёты в output собраны той же логикой, что работает в бою.
